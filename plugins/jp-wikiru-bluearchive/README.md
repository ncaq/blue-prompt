# jp-wikiru-bluearchive

[ブルーアーカイブ(ブルアカ)攻略有志Wiki](https://bluearchive.wikiru.jp/)
の情報を、
LLMがナレッジベースとして参照しやすい形に整えるためのプラグインです。

このプラグイン集が生まれた経緯と導入方法は、
リポジトリルートの[README.md](../../README.md)に書いてあります。

## 目的

LLMは『ブルーアーカイブ』について、
それらしい嘘をつきます。

学習時点が古いために新しい生徒やイベントを知らなかったり、
名前が似ているだけの生徒の性能を混ぜたり、
存在しないスキル名を自信満々に答えたりします。
ゲームの仕様は運営によって更新され続けるため、
モデルの内部知識だけで正確に答えるのは原理的に無理があります。

一方で公式は、
生徒の情報を機械可読な形では配信していません。
実際に参照できるまとまった情報源は有志のwikiであり、
日本語圏で網羅性と更新速度が高いのがこのwikiruです。

そこでこのプラグインは以下を担当します。

- wikiruのどのページに何が載っているかという地図を持たせて、調べる時の入口を固定する
- ページ構造やテーブルの読み方を伝えて、取得したページから必要な事実を取り出せるようにする
- 何度も引くことになる事実は、その都度取りに行かずに済むようにナレッジベースへ書き留める

LLMに記憶を頼らせるのではなく、
出典のある事実を引かせることが目的です。

## 提供するスキル

### [character-appellation](./skills/character-appellation)

キャラクターが自分や他のキャラクターをどう呼ぶかを調べるスキルです。
[キャラ呼称表](https://bluearchive.wikiru.jp/?%E3%82%AD%E3%83%A3%E3%83%A9%E5%91%BC%E7%A7%B0%E8%A1%A8)
を整形した一覧を同梱しています。

### [character-index-by-group](./skills/character-index-by-group)

キャラクターがどの学校のどの部活・組織に所属しているかを調べるスキルです。
[学校別キャラクター一覧](https://bluearchive.wikiru.jp/?%E5%AD%A6%E6%A0%A1%E5%88%A5)
を整形した一覧を同梱しています。

生徒個別スキルが1人ずつの深さを担当するのに対して、
こちらはキャラクター全体を見渡す索引を担当します。

### 生徒個別スキル(character-\*)

生徒のプロフィール・ステータス・スキル・絆ストーリー・ボイスといった、
ゲーム内の事実を調べるスキルです。

[ユウカ](https://bluearchive.wikiru.jp/?%E3%83%A6%E3%82%A6%E3%82%AB)
のような生徒個別ページから事実を載せているセクションだけを抜き出し、
[character-yuuka](./skills/character-yuuka)
のように生徒1人につき1つのスキルとして生成しています。

## ナレッジの生成方法

各スキルのナレッジは、
このリポジトリのF#プログラムでwikiruの記事から自動生成しています。

既存のナレッジをまとめて更新する時は、
リポジトリルートで以下を実行します。
`src/BluePrompt/Manifest.fs`に書いた対象を並列に取得して書き出し、
最後に`nix fmt`を1回だけ掛けます。

```console
dotnet run --project src/BluePrompt -- wikiru all --root .
```

新しいスキルを足す時は以下の個別コマンドで生成してから、
以後の一括更新に含めるために`Manifest.fs`へも対象を足します。

キャラ呼称表のスキルは、
テーブルを「誰が誰をどう呼ぶか」のレコードへ構造化した上で、
LLM参照用の`reference.md`と機械読み出し用の`appellation.json`を、
どちらもスキルの一部として同時に生成します。
JSONをリポジトリへ置くことで、
後段の生成処理が呼称を読み出すたびにwikiruへアクセスせずに済みます。

```console
dotnet run --project src/BluePrompt -- wikiru appellation --page 'キャラ呼称表' \
  --markdown-output plugins/jp-wikiru-bluearchive/skills/character-appellation/reference.md \
  --json-output plugins/jp-wikiru-bluearchive/skills/character-appellation/appellation.json
```

学校別キャラクター一覧のスキルは、
生徒1人を1つのテーブルにしたカードの敷き詰めから所属をレコードへ構造化して、
学校ごとの1つのテーブルへまとめた`reference.md`を生成します。

```console
dotnet run --project src/BluePrompt -- wikiru school --page '学校別' \
  --output plugins/jp-wikiru-bluearchive/skills/character-index-by-group/reference.md
```

生徒個別のスキルは1人分の量が少ないため、
スキル定義ごと1つの`SKILL.md`として生成します。
スキル名は出力先のディレクトリ名から導出されます。

```console
dotnet run --project src/BluePrompt -- wikiru student-skill --page 'ユウカ' \
  --output plugins/jp-wikiru-bluearchive/skills/character-yuuka/SKILL.md
```

生徒個別のスキルは、
AngleSharpでページを取得して本文と脚注だけを抜き出し、
編集リンクや広告やコメント欄を取り除き、
GFMのテーブルで表現できない結合セルを展開した上で、
pandocでMarkdownへ変換しています。
さらに折りたたみの中身を残し、
素材などを表す画像をaltの名前へ置き換え、
wiki独自の解説・考察を除いた事実セクションだけへ選別しています。

キャラ呼称表と学校別キャラクター一覧はpandocを通さず、
テーブルをレコードへ直接パースしてからMarkdownを書き出しています。
どちらもページのレイアウトのままでは読めないためです。
呼称表の脚注は末尾の定義ではなく、
呼称の直後の半角括弧の注記としてその場に置いています。
学校別キャラクター一覧は、
1人1つのテーブルとして敷き詰められたカードを、
学校ごとの1つのテーブルへ組み直しています。

wikiの更新を取り込みたい時は、
この節の冒頭の`wikiru all`で全てのナレッジをまとめて生成し直してください。

## 著作権についての立場

このプラグインは非公式であり、
『ブルーアーカイブ』の権利者とも、
wikiruおよび攻略有志Wikiの運営や執筆者とも、
一切関係がありません。

ゲーム内の事実をどこまで扱うかや、
ストーリーと台詞の線引きといったリポジトリ全体の方針は、
ルートの[README.md](../../README.md)に書いてあります。
ここにはwikiruを情報源にすることで生じる事情だけを書きます。

wikiの記事の著作権は各執筆者に帰属します。

### wiki独自のコンテンツは置かない

wikiruには二種類の価値があります。

ひとつは事実を先に集めてくれていることです。
ゲーム内の事実のほかに、
「小ネタ」にまとめられた現実世界の事実(武器の元ネタなど)もこれにあたります。
事実そのものは誰が書いても同じ表現になるため著作権は発生せず、
wikiruはその出所でもありません。
このリポジトリが取りに行くのはこちらです。

もうひとつは執筆者が自分の頭で書いた部分です。
解説文、
考察、
運用指南、
コメント欄のやり取りといった、
wikiruにしかないコンテンツがこれにあたります。
今のところそのままの形では置きません。
参照する必要がある時は、
要約と出典リンクに留めます。

### 構成したナレッジはリポジトリに置く

事実を抽出してMarkdownに構成し直したものは、
このリポジトリにコミットします。

置かずに毎回取りに行く運用も考えられますが、
同じページを何度も取得することになり、
wikiru側にも余計な負担を掛けます。
一度構成して置いておけば、
以降の参照はリポジトリの中で済み、
実際のアクセスはむしろ減ります。

置くのはあくまで事実であって、
取得したページをそのまま流し込んだものではありません。

### 学習のためのクロールとの違い

wikiruのrobots.txtは、
GPTBotとGoogle-Extendedを全面的に拒否しています。
一方で一般のクローラに対しては、
記事ページの取得を禁じていません。

これらは学習用データを集めるための巡回であって、
利用者の指示を受けて特定のページを読みに行く動作とは別物です。
実際にOpenAIも、
学習用の巡回と利用者の指示による取得を別のUser-Agentに分けています。

このプラグインが行うのは後者であり、
人がブラウザでそのページを開いて読むのと変わりません。
それを拒否する意思表示は、
robots.txtには書かれていません。

ただし読んだ結果を蓄積して配る点は、
その場で読んで閉じる閲覧より踏み込んでいます。
そこを支えているのが、
扱う対象を事実に限るという全体の方針です。

なお日本の著作権法は、
情報解析のために著作物を利用することを、
権利者の利益を不当に害しない限り認めています。
取得したページから事実を取り出す過程は、
これに当たると考えています。

### サーバに負担を掛けない

必要なページを必要な時にだけ取得します。
過度な頻度のアクセスは避けます。

### 出典を示す

ナレッジベースの各項目には参照元のページを記載します。
